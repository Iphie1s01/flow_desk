# FlowDesk — Your business. In sync.

Business operations platform for freelancers, agencies and small teams: customers (CRM), projects, tasks, invoices, payments, reports, team and activity in one workspace.

**Stack:** Next.js 15 (App Router, Server Actions) · TypeScript · Chakra UI v2 · Recharts · dnd-kit · Better Auth · Postgres on Neon · Cloudflare R2 (private files) · Resend (email).

## What makes it more than a UI
| Concern | How it is handled |
|---|---|
| Multi-tenancy | Every tenant table has `workspace_id`; **Row Level Security** policies check membership on every row. Composite foreign keys `(workspace_id, id)` make cross-tenant references impossible even for the table owner. |
| Roles | `owner`, `admin`, `member`, `viewer` enforced in Postgres policies (members only see projects they are assigned to and never see finance data; viewers are read-only; only the owner changes roles; admins cannot invite admins). |
| DB identity | The app connects as `flowdesk_app` (no BYPASSRLS). Each request runs in a transaction that sets `app.user_id` with `set_config(..., true)` (transaction-local, safe with Neon's pooler). Better Auth uses a *separate* `flowdesk_auth` role that can only touch auth tables. |
| Money | Integer minor units (kobo), never floats. Totals, tax (basis points, `round()`), paid amount, balance and **status are computed by the `invoice_summary` view**, so contradictory states cannot be stored. |
| Financial integrity | Triggers: issued invoices and their line items are locked; payments cannot exceed the balance, predate the invoice, sit in the future, or hit draft/void invoices (row lock prevents races); invoices with payments cannot be voided; payments are immutable; activity log is append-only. |
| Invitations | 32-byte random token, only its SHA-256 is stored, 7-day expiry, bound to the invitee's email, requires a verified account, single use. |
| Files | Private R2 bucket. Upload = permission check → pending row → 60-second signed PUT → server verifies object size → `ready`. Download = permission check → 60-second signed GET. Allow-listed types, 10 MB cap. |
| Abuse | Postgres-backed rate limiter (`hit_rate_limit`) on invites, payments and uploads; Better Auth's database rate limiter on sign-in/up/reset in production. |
| Errors | Postgres/zod errors are mapped to friendly messages; internals are logged, never returned. |

## Setup (≈10 minutes, all free tiers)
1. `npm install`
2. **Neon**: create a project. Copy the owner connection string (this is `DATABASE_URL_ADMIN`).
3. `cp .env.example .env.local` and fill in:
   - `DATABASE_URL_ADMIN` (owner), `APP_DB_PASSWORD`, `AUTH_DB_PASSWORD` (choose two strong passwords)
   - `DATABASE_URL` / `AUTH_DATABASE_URL`: the same host (use the `-pooler` host) with user `flowdesk_app` / `flowdesk_auth` and the passwords above
   - `BETTER_AUTH_SECRET` (`openssl rand -base64 32`)
4. `npm run db:migrate` — creates tables, roles, policies and sets the role passwords.
5. `npm run db:test` — runs the isolation and money-rule test-suite against your database (rolled back; 46 checks).
6. `npm run dev`, sign up, open the verification link (printed in the terminal if `RESEND_API_KEY` is empty), then
7. `npm run db:seed -- you@email.com` — adds the demo workspace *Northstar Creative Studio* (18 customers, 12 projects, 65 tasks, 24 invoices, reconciled payments) owned by you.

### Optional
- **Google sign-in**: create OAuth credentials, redirect URI `http://localhost:3000/api/auth/callback/google`, set `GOOGLE_CLIENT_ID/SECRET`.
- **Email**: `RESEND_API_KEY`, `MAIL_FROM` (verify a domain for production).
- **File uploads**: create a private R2 bucket, add `R2_*` variables and a CORS rule allowing `PUT` from your app origin.
- **Public read-only demo**: sign up a demo user, then `npm run db:seed -- you@email.com demo@email.com` makes it a `viewer`; set `DEMO_EMAIL` / `DEMO_PASSWORD` to show the "Explore the read-only demo" button.

### Deploy
Vercel: import the repo, add the environment variables (never `DATABASE_URL_ADMIN`), set `BETTER_AUTH_URL` and `NEXT_PUBLIC_APP_URL` to your domain. Run `db:migrate` from your machine against Neon.

## Project map
```
db/migrations/001_auth.sql   Better Auth tables (generated by its CLI)
db/migrations/002_core.sql   schema · constraints · triggers · RPC functions · RLS · grants
db/seed.sql                  demo workspace
scripts/db.ts, rls-test.ts   migrate / seed / test runner
src/lib/                     db (RLS transactions), auth, session (ctx), queries, validators, money, csv, storage
src/app/actions.ts           all mutations (Server Actions): validate → authorise → write → log
src/app/(app)/…              overview, customers, projects, tasks, invoices, payments, reports, team, activity, settings
src/components/              shell + command menu, forms, kanban (drag-and-drop), charts, invoice form
```

## Keyboard
`⌘/Ctrl+K` command menu · `/` search · `N` quick create · `Esc` closes dialogs. Shortcuts are ignored while typing.

## Not included yet
Online payment collection (Paystack/Stripe webhooks need signature verification + idempotency, `payments.provider_reference` is already unique for it), comments, saved custom filters, customizable dashboard layout, server-generated PDFs (the invoice prints cleanly to PDF from the browser).
